# 长征：万水千山

统帅视角的长征文字游戏 —— 思政实践作业作品。你在一张 2000×4600 的路线示意图上一格一格往北走，
手里只有四条资源：**建制（兵）· 口粮（天）· 时窗（天）· 民心**。木牌上记下的人名，是这趟路唯一带得走的东西。

- **线上玩**：<https://dybfvs37.qwenwork.host/> —— 由**千问办公（qwenwork.cn）托管**，不在 Qoder Sites 控制面里，**本机没有该站凭据，不能从命令行发布**。更新方式：把 `游戏/` 5 个文件打成桌面交接包交千问办公同名覆盖站点根目录。截至 2026-10-26 该站内容仍是 10-20 的第六轮版（缺第八~十二轮），待发。
- **本地玩**：双击 `游戏/index.html`（零依赖，离线可用，进度存本机浏览器）
- **技术形态**：纯静态前端，5 个文件、约 191 KB，没有 npm、没有构建、没有后端、没有外链

> 下面是给"接手部署/维护的人（或 AI 工具）"看的交接说明；只想玩的话，点开上面的链接就够了。

## 一、怎么发布（只有一种正确做法）

**站点根目录 = `游戏/`**，首页 = `游戏/index.html`。

发布清单（就这 5 个文件，共约 191 KB）：

| 文件 | 作用 |
|---|---|
| `游戏/index.html` | 首页 + 骨架 DOM |
| `游戏/style.css` | 全部样式（含 760/430px 与触屏三档） |
| `游戏/data.js` | 纯数据：节点/边/事件/卡/道具/史料/战友 |
| `游戏/game.js` | 全部逻辑（单文件 IIFE） |
| `游戏/favicon.svg` | 标签页图标 |

要点：

1. **不要**把 `.md` 设计文档、`测试/`、`00-`～`13-` 那些文件发到线上 —— 那是本地施工记录，含未定稿内容。
2. **不要**为发布而拆分/合并/重命名上述文件，也不要改 `index.html` 里的相对引用。
3. 如果托管平台只能把**整个文件夹**当根目录：项目根已放了一个 `index.html`，它只做一件事 —— 立刻跳转进 `游戏/index.html`。这种情况下线上 URL 里会出现中文路径（已 URL 编码，能正常访问），但**首选还是把 `游戏/` 单独当根**。
4. 服务器**只需静态文件**，不需要任何 rewrite / API / 鉴权。存档全在浏览器 `localStorage`（键名 `cwqs_save_v1` 和 `cwqs_meta_v1`）。
5. MIME：`.svg` 需 `image/svg+xml`（几乎所有平台默认就对）；`.js`/`.css` 默认即可。**必须**按 `charset=utf-8` 提供，中文剧情不能乱码（`index.html` 已声明）。

发布前自检（Node 就能跑，无依赖）：

```bash
node 测试/发布自检.js        # 15 项检查，退出码 0 = 可直接发布
node 测试/data校验.js 游戏/data.js   # 游戏数据校验，应为 0 错误
```

| 位置 | 模块 | 职责 |
|---|---|---|

| `game.js:121` | `Router` | 弹窗栈。**全站不用下拉菜单**，一律 链接 + 弹窗 |

| `game.js:260` | `MapView` | SVG 大地图（viewBox 2000×4600）+ 拖拽/滚轮/双指缩放 + 视野遮罩 + **下一站判定**（`frontNodes / nextNode / goNext`） |
| `game.js:713` | `Game` | 主流程：`march`（行军 tick）→ `compute`（结算）→ `applyChoice` → `commit` → `finishChoice` → `afterResolve`；大关卡首破的「三样只能带一样」在 `gateSpoils`（`game.js:1271`）；行进事件文案在 `rollMoveEvent / pickVariant`（`game.js:1054`、`game.js:1087`） |

| `game.js:1830` | `Ending` | `run` 走到吴起镇「念名字」（含 B 空格 / C 文物两段条件文本）；`fall` 是失败终章「没有走到吴起镇」（`game.js:1872`） |

## 五、已知坑 / **禁止修改清单**

接手方最容易"顺手修坏"的地方，逐条点名：

1. **`data校验.js` 会报 6 条「开局 6 张卡无发放途径」的 warning —— 这是误报，别改。** 开局手牌是写死在 `game.js:84` 的 `defaultState().hand` 里的，故意不从 `data.js` 发放。**不要**为了让校验输出变干净去 data.js 里加发放节点。同理 `10-*.md` §(短板) 里写的「打散这条失败线跑测里几乎不自然触发」是当时的观察 —— 2026-10-25 已用 `fallLimit: 3` + `Ending.fall` 补上失败终章（见 `13-*.md`），**不要再把它改回"永远有收容队"**。
2. **选项按钮上不许预先标数值代价。** 这是用户明确要求（"按下后才亮账"）。如果你看到选项旁边没有 `+3 粮` 之类的标注，**那是设计，不是缺失**，别补。
3. **不许引入外链资源**（CDN、Google Fonts、远程图片、地图瓦片、统计脚本）。理由：这站要在内网/离线也能开，且 `file://` 双击必须继续可用。因此也**不许**改成 ES module、不许用 `fetch`。字体是 `Songti SC / SimSun` 等本机字体，手机上回退成系统宋体**属正常**。
4. **数值只在 `BALANCE`（`game.js:35`）改。** 不要在 `data.js` 里散着写死资源数字。曲线是跑测台校准出来的，改动口径见 §六。
5. **`Game.debug` 挂在 window 上不是漏洞**，是跑测台的接口，别删。
6. **地图坐标是示意图，不是精确地理**。省界/河道是手绘近似，`index.html` 页脚已声明。别"修正"成真实地图（那需要外部瓦片，违反第 3 条）。
7. **`localStorage` 按 origin 隔离。** 本机 `file://` 的存档**不会**出现在线上；换域名也是新档。这是预期行为，别为此写同步逻辑或后端。
8. **`测试/balance-bench.js` 用 `file:///` 注入 `<script>` 才能工作**（`file://` 下 `fetch` 被 CORS 挡）。它在 http 网址上跑不了 —— 需要跑数值时请在本地双击 `游戏/index.html` 后用，不要试图改成 http 兼容。
9. **「玩家须知」只在第一次进游戏时弹**（看 `Store.s.flags.sawNotes`），之后靠地图左下角的朱红「须知」章重开。别改成每次都弹，那会变成拦路。
10. **抉择弹窗是 `closable:false + blocking:true`**，玩家点不关它；`Router.closeAll()` 里那句"只有真按过选项才结清"的守卫是防崩的，别删。
11. **`MOVE_EVENTS` 选项上的 `anch:[...]` 不是冗余字段，别删。** 它是"选项里提到的每一个实体，必须在**这一次屏幕上的正文**里出现过"这条口径的可执行版本（用户反馈「半里路的垫木」那条事件读起来没头没尾之后加的）。`测试/data校验.js` 会拿它去查每一条正文和每一个不带自己 options 的变体；删掉 anch = 关掉这道闸。变体可以自带 `options`（不带走事件级那几条，`pickVariant` 就是这个合并口径），**自带 options 的变体必须自己把锚点交代全**。改完跑 `node 测试/data校验.js 游戏/data.js --对账` 能打出「事件 × 变体 × 选项 × 锚点」对账清单。
12. **`TEAM` 里组员的 `duty` 是空的，那是"还没确认"，不是漏写。** 这是要署名的作业材料（队长丁晨逸，组员贺智杰、冯天秦、朱培森、吴柏燃），分工一句话必须由本人自己给，**工具不得代拟**。名单、课程、选题口径同理：只改 `data.js` 的 `COURSE` / `TEAM`，不要在 `game.js` 或 `index.html` 里另抄一份。
13. 改完全量自检：`node --check 游戏/game.js && node 测试/发布自检.js`，并在浏览器 Console 确认无报错。

## 六、数值现状（发布不需要，但改的人要知道）

`BALANCE` 当前口径（2026-10-26 落地 C11，详见 `15-C11数值落地与500局复核-v1.md`）：初始 兵 100 / 粮 11 天 / 时窗 6 天 / 民心 40；主走廊 42 格，每格 −1 粮 −1 时；大关卡首破不再直接回补，改成**粮 +2 / 时 +2 / 兵 +2 三样只能带一样**（`gateSpoils`，此前是 3/3/6）；断粮额外折 6 支建制（`hungerLoss`，此前 3）；时窗归零只压成**一格**（这一格折损翻倍 + 最多一场遭遇战），随后挣回 2 天（`pursuitGrace`，此前 3）；民心 ≥70 且真断粮时百姓接济，一局至多 3 次；战友在队上限 6，但**一个战友一次最多只挡 2 支建制**（`mateSave: 2`，此前是 4）；打散 + 违纪累计第 3 次触发失败终章（`fallLimit: 3`）。

以下两段是**改数值之前**的跑测记录，留着是为了说明每一轮为什么这么拧，**不要**当作现行难度的描述：

跑测台实测（2026-10-25 复跑，5 局平均；数据详见 `13-平衡与结局修整-v1.md`）：贪心策略 5/5 走完、终局兵 46.4、突发事件 10.8 次/局；稳健 5/5、终局兵 48.2；乱点 4/5（其余 1 局转入失败终章）；违纪到底 0/4 走完 —— 全部在第三次收账时进入失败终章。

随机打法大样本（2026-10-26，各 500 局，见 `13-*.md` §七）：选项随机的 `random` 通关率 73.8%、每键都随机的 `chaos` 78.8%，**期望 1.27~1.36 条命通关**；两命内 93%~96%，三命内 98% 以上。所有失败局都是违纪终章，**没有一局是兵打光/粮耗尽/走不动** —— 资源当时只影响结算，不影响生死。再要加难度，杠杆是初始资源或断粮/时窗惩罚，不是继续削战友 —— 这一条已在同日按 C11 执行。

C11 落地后的复核（2026-10-26，四策略各 125 局共 500 局，详见 `15-*.md` §三）：`perfect` 125/125 通关、一命 6.4%；`veteran` 125/125、一命 5.6%；`novice` 125/125 但**无一局不死人**（1 死 116 局、2 死 9 局）；`chaos` 62/125（49.6%），63 局三次机会用尽，期望 2.02 条命。失败口径仍然只有违纪终章一条 —— 资源耗尽不出局，这是设计选择。要改这一点得动 `Flow`，不是继续拧 `BALANCE`。
